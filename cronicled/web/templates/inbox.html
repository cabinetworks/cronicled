{# cronicled/web/templates/inbox.html #} {# One proposal is one block, not a table row. It was a table, and the buttons sat in the last cell of a row that was then followed by up to four full-width detail rows. Reading down the page, a proposal's buttons appeared BELOW the previous proposal's detail lines and ABOVE its own filename, so they looked like they belonged to the row beneath. That was misread in use -- reported as "the top result showed a button the first time and not the second" -- and on a page whose buttons write to a media library, a control that appears to belong to the wrong row is a hazard rather than an untidiness. A block keeps a proposal and its controls in one bordered box, so which buttons act on which file is a fact about the layout rather than something to be inferred from vertical position. What a table did better, and what is deliberately preserved: five scores were comparable at a glance down an aligned column. The score here keeps a fixed-width slot at a consistent position in every block, for the same reason. No JavaScript and no build step: one stylesheet, inline, short enough to read in a sitting. The form markup below is unchanged from the table version -- tests assert the whole set of controls a row offers, including each action path, and that guarantee is worth more than tidier markup. #}
